## ۱. نمای کلی

پلتفرم دو سطح دارد:

| سطح | مخاطب | کانال |
|-----|--------|--------|
| **عمومی** | بیمار / لید | وب‌سایت (و اپ آینده) |
| **ERP** | شرکت آرمونیا، شعب، کلینیک‌ها، پزشکان، پرسنل | پنل وب نقش‌محور |

همهٔ کانال‌ها از طریق **API** به هسته وصل می‌شوند. فرآیندهای داخلی فقط در ERP انجام می‌شود؛ وب عمومی برای جذب، رزرو، مشاوره و پنل بیمار است.

```
[Website FA/AR/EN] ──┐
[Patient App later] ─┼──► API Gateway ──► Auth/RBAC ──► Tenant Scope
[ERP Web] ───────────┘                      │
                                            ▼
                    Modules: CRM · Patients · Appointments · Finance · …
```

## ۲. مدل سازمانی (Multi-Tenant / Multi-Branch)

سلسله‌مراتب:

```
Organization (آرمونیا)
  └── Country
        └── Province / City
              └── Branch (شعبه)
                    └── Clinic (کلینیک طرف‌قرارداد یا داخلی)
                          └── Doctor / Service / Staff
```

- **Multi-Tenant:** هر سازمان/شبکه مرز دادهٔ جدا دارد (آمادگی چند برند/کشور).
- **Multi-Branch:** فیلتر و گزارش‌ها روی شعبه؛ سوییچر شعبه در هدر ERP.
- **Clinic scope:** ظرفیت، خدمات، پزشکان و تسویه در سطح کلینیک.

در UI: `BranchSwitcher` + `ClinicScope` badge اجباری برای نقش‌های عملیاتی.

## ۳. ماژول‌ها (مرز منطقی)

| ماژول | مسئولیت اصلی |
|--------|----------------|
| Dashboard | KPI فروش، سود، شعب، پزشکان، لحظه‌ای |
| CRM | لید، تماس، پیگیری، قیف، وضعیت فروش |
| Patients | پرونده، مدارک، عکس، تاریخچه، نسخه |
| Appointments | رزرو، تقویم پزشک، کنسلی، لیست انتظار |
| Doctors | پروفایل، برنامه، قرارداد، درصد، عملکرد |
| Clinics / Branches | اطلاعات، ظرفیت، گزارش |
| Marketing | کمپین، بودجه، ROI، تقویم محتوا، سوشال |
| Finance | اقساط، دریافت/پرداخت، پورسانت، تسویه |
| Contracts | بیمار / پزشک / کلینیک + امضای دیجیتال |
| HR | پرسنل، حضور، مرخصی، حقوق |
| Tickets | پشتیبانی داخلی |
| Notifications | پیامک، واتساپ، ایمیل، پوش |
| Users / RBAC | نقش، دسترسی، لاگ فعالیت |
| Settings | شعب، خدمات، تعرفه، برند، جغرافیا، زبان |

معماری ماژولار: هر ماژول API و UI جدا با وابستگی از طریق رویداد/قرارداد مشترک (بیمار، نوبت، فاکتور).
