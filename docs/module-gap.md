# فاصلهٔ ماژول‌ها — `apps/platform` vs مشخصات کامل

> تاریخ ممیزی: ۱۴۰۵/۰۵/۰۳ · هدف: بستن شکاف دموی غیرعملیاتی

## وضعیت قبل از این فاز

| حوزه | موجود | کمبود |
|------|--------|--------|
| داده | mock در حافظه | بدون persistence · refresh = از دست رفتن تغییرات |
| ERP صفحات | داشبورد، CRM، نوبت، بیمار، تنظیمات | پزشکان، کلینیک، شعبه، مارکتینگ، مالی، قرارداد، HR، تیکت، اعلان، کاربران |
| عمومی | خانه، خدمات، پزشکان، رزرو، پنل بیمار | نمونه‌کار، بلاگ، مشاوره، تماس، FAQ |
| RBAC | نوع نقش + لیبل | بدون ماتریس اجرایی · بدون سوییچر نقش · منوی فیلترنشده |
| API | GET mock برای leads/patients/appointments/branches | بدون POST/PATCH/DELETE · بدون ماژول‌های دیگر |
| اعلان | — | بدون صف / لاگ ارسال |
| i18n | فقط FA در UI | بدون ساختار en/ar |
| چندمستأجری | BranchSwitcher نمایشی | بدون org/tenant در مدل داده |

## برنامهٔ بستن شکاف

1. Prisma + SQLite + seed فارسی غنی
2. Route Handlers کامل برای همهٔ ماژول‌ها
3. Session cookie mock + ماتریس RBAC در کد + فیلتر منو
4. صفحات ERP/عمومی operable با CRUD پایدار
5. Notification stub روی رویدادها (رزرو و …)
6. دیکشنری‌های fa|en|ar برای شِل و ناوبری

## وضعیت پس از فاز پیاده‌سازی

همهٔ ماژول‌های فهرست‌شده دارای صفحهٔ ERP/عمومی + API + persistence در SQLite هستند.
جریان پذیرش: لید → قیف → نوبت → پرونده → مدرک → لغو → waitlist → کمپین → قسط — پایدار پس از refresh.
